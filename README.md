## 项目简介
    当前项目主要为了解决电商行业生成素材问题，比如文生图，图生图，文生视频，图生视频，首尾帧视频（2张图片生成视频），全智能多帧视频。解决的是目前平台收费贵，对于刚起步小伙伴费用高问题。我这个项目支持自己配置平台API。自己部署本地电脑使用。也方便小     伙伴用AI进行二次开发。因为此项目大部分都是用AI开发的。
    未来还会扩展，画布功能和数字人等核心功能。目的就是给自己用和分析等。将不断持续扩展优化功能。
    
### WooVisAgent 是什么？
 一句话定位：一个自托管的、模型无关的 AI 图片 / 视频创作控制台。

它不绑定任何一家模型厂商。你把自己的模型配置（endpoint、key、支持的参数、能力边界）填进去，剩下的创作、提交、进度、作品管理它全包了。要接新的厂商？加一条配置，不改一行业务代码。

核心使用链路就四步：

配模型：在模型配置里填 endpoint、鉴权、默认参数、能力声明。

写需求：在对话里描述你要什么，或者直接在面板里填提示词、上传素材。

看进度：提交后实时看生成状态，长任务后台跑，不卡界面。

管作品：生成结果进作品库，可筛选、可下载、可复用。

## 二、五个值得说的亮点

### 亮点 1：模型无关，换厂商只改配置

这是整个项目的设计内核。所有厂商差异都被收敛到两层纯数据里：

- **交付预设（Preset）**：每个厂商一套数据，描述它的请求长什么样、参数怎么拼。
- **交付模板（Template）**：你覆盖在预设之上的个性化设置（分辨率、时长、是否带音频等）。

新增一个厂商 = 加一条预设数据，而不是写一套协议类。目前内置了多个开箱预设，覆盖常见的几类网关形态：

| 预设              | 适用场景     | 说明              |
| :---------------- | :----------- | :---------------- |
| OpenAI 视频类     | 标准兼容接口 | 通用文生视频      |
| 百炼 DashScope    | 阿里系模型   | 文生视频 + 首尾帧 |
| 百炼 Legacy       | 旧版接口     | 兼容老字段写法    |
| SiliconFlow       | 硅基流动     | 标准兼容          |
| 火山方舟 Seedance | 字节系模型   | 高级多帧、首尾帧  |
| 百炼媒体视频      | 媒体网关     | 首尾帧平铺写法    |

> 📷 配图建议：放一张「模型配置下拉 + 预设列表」的截图，旁边标注"换厂商就是选个预设"。

### 亮点 2：三种视频模式，对标即梦的交互

点开视频生成，不是只有一个"文生视频"按钮，而是三种**互斥**的模式，由你按素材情况选择：

- **全能生成（omni）**：默认模式，涵盖纯文生视频，也能吃参考图/参考视频/参考音频。
- **首尾帧（firstLastFrame）**：你给第一帧和最后一帧，模型补中间的过程，适合做转场、定格动画。
- **智能多帧（keyframes）**：给 2–10 张关键帧，模型按序生成，适合复杂镜头编排。

每种模式对应的素材类型、数量上限，都由"能力声明"描述并落库，前端据此自动禁用不支持的模式——你不用去翻文档猜哪个能用。

### 亮点 3：异步长任务，界面不卡

视频生成是长任务，绝不该阻塞前端。提交后请求立刻进消息队列，由一个独立的工作进程消费执行，完成后通过实时通道推回前端。

- 提交即时返回，不用干等；
- 工作进程挂了也不丢任务，队列里有兜底；
- 框架层把单条消息的执行超时放宽到 30 分钟，避免长视频被框架误杀进死信队列。

### 亮点 4：Agent 给建议，但不越权

项目里接了微软的 Agent 框架，但它的职责被划得很死：**只做决策，不碰执行**。

它帮你改写提示词、推荐参数组合，但**绝不**替你提交任务、也**不**跑轮询。提交和执行永远走稳的那条链路（交付框架 + 消息队列）。这样 Agent 再怎么"聪明"，也不会把系统状态搞乱。

### 亮点 5：实时进度，推送 + 轮询双保险

实时进度用推送通道推，但我们也留了轮询兜底——因为推送在弱网/多实例下可能漏一条。前端收到推送只记时间戳，**不会**因为"以为收到了"就停掉轮询。漏一条就永久卡住的情况，从设计上被堵死了。

## 三、谁适合用

- 想**自己托管**一套创作工具、数据不进第三方后台的开发者；
- 同时在用多家模型厂商、受够了改代码接模型的工程师；
- 做视频素材、需要首尾帧 / 多帧控制的创作者；
- 想研究 .NET + 消息队列 + 实时推送整套异步架构的同学。
