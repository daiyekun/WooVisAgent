# WooVisAgent 产品需求文档（PRD）

> 版本：1.0
> 适用读者：产品、设计、研发、测试
> 文档性质：需求与功能规格说明（不含代码实现）

---

## 1. 文档目的与范围

本文档定义 WooVisAgent（以下简称"本系统"）的产品定位、目标用户、功能需求、非功能性需求与数据/状态模型。

系统目标是：**让创作者用一句话或一张图，接入自己拥有的图像/视频大模型，完成图片与短视频的生成、管理、复用，并在对话流中持续迭代**。

本文档仅描述"要做什么"与"做到什么程度"，不描述"如何实现"。实现细节见《系统架构文档》。

---

## 2. 产品概述

### 2.1 一句话定位

一个**自托管、模型无关**的 AI 图片/视频创作控制台：用户配置自己的模型服务地址与密钥，通过对话或表单提交生成任务，实时查看进度，并将满意产物收藏进个人作品库。

### 2.2 核心价值

| 价值点 | 说明 |
| --- | --- |
| 模型自持 | 不绑定任何厂商，用户自带 OpenAI / 阿里云百炼 / 火山方舟(即梦) / SiliconFlow / 本地 ComfyUI 等模型 |
| 厂商差异配置化 | 新厂商接入通过"预设 + 交付模板"表达，用户改配置即可，无需改代码 |
| 对话式创作 | 图片与视频共用一条对话流，支持多轮迭代与素材引用 |
| 实时可追踪 | 生成进度通过实时通道推送，并辅以轮询兜底，进度不丢、不卡死 |
| 资产管理 | 任务产物可"选秀"收录进作品库，支持分组与检索 |

### 2.3 使用流程（端到端）

1. 注册 / 登录账号。
2. 在「模型配置」中新增并启用至少一个图像模型与一个视频模型（填写 endpoint、密钥、默认参数）。
3. 在「对话创作」输入提示词（或上传参考图/视频/音频），选择生成方式与模型，提交。
4. 实时查看生成进度，完成后产物出现在对话流与「任务列表」。
5. 满意的产物「选秀」进「我的作品」，可检索、复用、删除。
6. 在「模型配置」中通过 Agent 助手润色提示词、规划视频参数（仅建议，不自动提交）。

## 3. 用户角色

| 角色 | 说明 | 权限范围 |
| --- | --- | --- |
| 创作者（默认） | 系统主要使用者 | 仅能操作**自己**的模型配置、会话、任务、作品 |
| 部署/运维者 | 启动与运维本系统 | 管理运行环境、数据库、消息队列、单实例约束 |

> 数据隔离原则：所有用户资源按 `OwnerId` 隔离。一个部署可服务多用户，但用户之间互不可见彼此的配置、会话与作品。

## 4. 功能需求

### 4.1 账号与鉴权

| 编号 | 功能 | 需求描述 | 验收要点 |
| --- | --- | --- | --- |
| AUTH-1 | 注册 | 支持邮箱 + 密码注册（密码 ≥ 8 位）；可选邮箱验证码 | 注册成功即签发登录令牌 |
| AUTH-2 | 登录 | 支持邮箱或用户名登录 | 凭据正确返回令牌与用户信息 |
| AUTH-3 | 验证码 | 支持获取邮箱验证码（按配置决定是否必填） | 开发态可回显验证码便于联调 |
| AUTH-4 | 会话恢复 | 刷新页面后凭令牌恢复当前用户资料 | 未登录访问受保护页跳登录 |
| AUTH-5 | 鉴权保护 | 除注册/登录/验证码外，所有业务接口需登录 | 未带有效令牌返回 401 |

**说明**：令牌采用 JWT，WebSocket 握手通过 `access_token` 查询参数传递。

### 4.2 模型配置管理

让用户把"自己的模型"接进来，是本系统的核心前置能力。

| 编号 | 功能 | 需求描述 |
| --- | --- | --- |
| MODEL-1 | 新增配置 | 填写名称、供应方(Provider)、分类(图像/视频/语言模型)、模型标识(ModelKey)、接口地址(Endpoint)、密钥(ApiKey)、默认参数(ParamsJson) |
| MODEL-2 | 列表/详情 | 按分类筛选；详情接口向**配置所有者**回显明文 ApiKey 供编辑回填 |
| MODEL-3 | 编辑/删除 | 更新时 ApiKey 留空表示沿用原值；删除需确认 |
| MODEL-4 | 启用/停用 | 停用后不出现在"新建任务"的模型下拉中 |
| MODEL-5 | 默认模型 | 同用户同分类内可设一个默认模型（互斥），用于预填 |
| MODEL-6 | 连通性测试 | 支持"已落库配置测连"与"未落库草稿试连"两种，返回成功/耗时/错误信息 |
| MODEL-7 | 供应方模型清单 | 按供应方拉取其公开支持的模型清单，辅助选择 ModelKey |
| MODEL-8 | 视频交付模板 | 视频类模型可附加"交付模板"：覆盖预设推断出的请求路径、字段映射、产物取回方式、能力声明 |

**预设（内置，开箱即用）**：

| 预设名 | 适用厂商 | 关键特征 |
| --- | --- | --- |
| `openai-videos` | OpenAI 及兼容网关 | 提交 `/v1/videos`，轮询取状态，产物需另调接口下载二进制 |
| `dashscope-video` | 阿里云百炼（新版） | `X-DashScope-Async` 异步；视频地址 24h 有效需转存 |
| `dashscope-legacy-video` | 百炼旧版 text2video/image2video | 路径同新版，分辨率用星号写法 |
| `dashscope-media-video` | 百炼 Wan 2.7+ 首尾帧 | 入参为 `media` 数组（首帧/尾帧/音画） |
| `siliconflow-video` | SiliconFlow | 轮询用 POST，按 `requestId` 查询 |
| `ark-seedance` | 火山方舟(即梦) | `content` 数组 + role 区分素材；小写 `720p`；首尾帧 `ratio=adaptive` |

**能力声明（视频模型）**：每个视频模型声明支持的模式(omni/firstLastFrame/keyframes)、参考图/视频/音频上限、关键帧上限、首尾帧是否要求 adaptive 比例。前端据此禁用不支持的模式与超额素材。

**安全**：ApiKey 仅在服务端存储，出参一律脱敏（不回传明文，仅详情接口对所有者回显）。

### 4.3 图片生成

| 编号 | 功能 | 需求描述 |
| --- | --- | --- |
| IMG-1 | 文生图 | 输入提示词（可含负向提示词）与模型自定义参数提交 |
| IMG-2 | 图生图 | 上传参考图（素材库/上传），作为生成参考 |
| IMG-3 | 异步提交 | 提交仅落库 + 投递消息，真正生成在后端 Worker 完成 |
| IMG-4 | 参数规格 | 参数表单由模型配置的 ParamsJson 动态渲染（数字/文本/布尔/下拉，含范围与默认值） |
| IMG-5 | 提交校验 | 模型不存在/未启用、提示词为空等需前置拦截并返回明确错误 |

**参考素材上传**：支持图片（≤10MB）、视频/音频（≤100MB/个），单次最多 50 个；返回可直接引用的访问地址。

---

### 4.4 视频生成（三种模式）

视频生成支持三种**互斥**模式（一次请求只能选一种），对齐即梦/Seedance 的参考模式：

| 模式 | 标识 | 需求描述 | 素材要求 |
| --- | --- | --- | --- |
| 全能生成 | `omni` | 默认模式。**无素材=纯文生视频**；有素材=图/视频/音频多模态参考 | 在提示词中用 `@图片1`、`@视频1`、`@音频1` 指定角色 |
| 首尾帧 | `firstLastFrame` | 首图→尾图，中间过程由提示词描述 | **恰好 2 张图**（首帧、尾帧）；首尾帧时比例须为 adaptive |
| 智能多帧 | `keyframes` | 多张关键帧按顺序串联成一镜到底 | 2–10 张参考图，模型自动插值 |

**视频生成需求表**：

| 编号 | 功能 | 需求描述 |
| --- | --- | --- |
| VID-1 | 模式选择 | 点击视频生成时下拉选择模式，默认全能 |
| VID-2 | 素材引用 | 在提示词中以 `@` 引用已上传素材，指定其角色（图/视频/音频） |
| VID-3 | 模式-素材校验 | 首尾帧不足 2 张、智能多帧张数越界、文生视频但模型不支持等，需前置返回友好错误 |
| VID-4 | 参数 | 时长、分辨率(480P/720P/1080P)、画幅(16:9/9:16/1:1/adaptive 等)、种子等，按模型能力动态呈现 |
| VID-5 | 厂商无关 | 同一套"模式+素材+参数"提交，由交付预设/模板翻译成不同厂商的请求体形状 |
| VID-6 | 长任务支持 | 视频轮询最长可达 20 分钟，系统须保证任务不被框架超时掐断 |

**关键约束（来自厂商文档，必须由系统强制）**：
- 首帧 / 首尾帧 / 全模态参考**不可混用**于一次请求。
- 首尾帧时 `ratio` 必须为 `adaptive`，否则异步报 `TaskTypeConstraint`。
- 分辨率大小写敏感（方舟要小写 `720p`，百炼要 `720P`）。
- 百炼视频地址仅 24 小时有效，取到后必须立刻转存。

### 4.5 对话创作

图片与视频共用同一条对话流，降低用户切换成本。

| 编号 | 功能 | 需求描述 |
| --- | --- | --- |
| CHAT-1 | 多轮对话 | 在同一会话内连续提交生成，历史消息与产物可回放 |
| CHAT-2 | 生成方式面板 | 对话输入区含"生成方式"面板：选择图像/视频、选择模型、视频模式与素材 |
| CHAT-3 | 素材引用 | 支持上传并在提示词中以 `@` 引用图片/视频/音频 |
| CHAT-4 | 输入区折叠 | 整个输入区（含生成方式面板）可折叠，避免遮挡对话内容；折叠状态本地记忆 |
| CHAT-5 | 提交后清空 | 提交成功后清空输入框文字、已选图片与视频引用，防止重复提交 |
| CHAT-6 | 显式结果反馈 | 提交函数返回明确成功/失败布尔，前端据此决定是否清空与继续轮询 |
| CHAT-7 | 图生图续作 | 上一轮产物可作为下一轮参考图继续生成（"改自上一轮"） |

### 4.8 会话管理

| 编号 | 功能 | 需求描述 |
| --- | --- | --- |
| CONV-1 | 会话列表 | 分页查询，按类型(图像/视频)/关键词筛选；提供总数与分类计数 |
| CONV-2 | 取/建会话 | 进入对话页先 `ensure` 空会话拿 id；可显式新建/重命名 |
| CONV-3 | 会话详情 | 返回会话 + 全部消息 + 该会话下任务，供历史回放 |
| CONV-4 | 删除级联 | 删除会话级联删除其消息与任务；已选秀进作品库的产物保留，并提示影响面 |

**会话与任务关系**：会话与任务 1:N。每次提交在该会话下追加一对消息并新建一个任务。

### 4.9 Agent 智能建议（仅建议，不提交）

基于 Microsoft Agent Framework，提供两类辅助能力：

| 编号 | 功能 | 需求描述 | 边界 |
| --- | --- | --- | --- |
| AGENT-1 | 状态查询 | 查询 Agent 是否可用（是否已配置可用语言模型） | — |
| AGENT-2 | 提示词润色 | 把口语化描述改写为模型易理解的提示词，返回润色后提示词、负向提示词、建议 | 只产出建议，绝不提交生成任务 |
| AGENT-3 | 视频参数规划 | 一句话需求 → 视频参数建议（提示词/模型/时长/分辨率/画幅） | 只建议；模型推荐只能从用户已启用视频模型中选 |

**设计红线**：Agent 只做"理解意图 / 改写提示词 / 推荐参数"，**不提交任何生成任务、不参与轮询与落盘**。即使模型幻觉，最多导致"建议不靠谱"，不会"凭空花钱"。

### 4.10 实时进度推送

| 编号 | 功能 | 需求描述 |
| --- | --- | --- |
| RT-1 | 实时通道 | 通过 SignalR 将任务创建、状态变更、进度、完成、失败推送到页面 |
| RT-2 | 轮询兜底 | 聊天页与任务列表均保留轮询兜底；收到推送只记时间戳，**不停止轮询**（防止漏推永久卡住） |

## 5. 非功能性需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 提交响应应在秒级（仅落库+投递）；生成耗时取决于外部模型（视频可至 20 分钟） |
| 并发 | 同一套数据库/队列只允许**一套** Api + Worker 运行（单实例约束），避免状态推送被多实例分流导致进度卡死 |
| 可用性 | 单实例故障不影响已提交任务的最终落盘（Worker 崩溃由"僵尸任务清扫"收敛为失败） |
| 安全 | 全站登录鉴权；ApiKey 服务端存储、出参脱敏；上传校验类型/大小/数量 |
| 合规 | 输出不出现"AI 生成"等敏感标识；不在前端夸大生成能力 |
| 可观测 | 通过 OpenTelemetry 导出链路（含大模型调用 span）、结构化日志 |
| 兼容 | 前端兼容不同厂商交付差异（大小写分辨率、轮询方法 GET/POST、产物取回方式 url/content） |

## 6. 数据模型概览

> 以下为领域实体与关键字段的需求描述，非表结构定义。

| 实体 | 关键属性 | 说明 |
| --- | --- | --- |
| 用户(User) | Id、邮箱、用户名、密码哈希、角色 | 账号体系，资源归属 `OwnerId` |
| 模型配置(ModelConfig) | 名称、分类、供应方、模型标识、接口地址、密钥(脱敏)、启用、默认、参数规格、视频交付模板、能力声明 | 用户自持模型 |
| 生成任务(GenerationTask) | 类型(图像/视频)、状态、进度、模型、提示词、参数、输入素材、产物、错误、时间线、会话Id、来源任务Id、是否已选秀 | 图片与视频共用 |
| 会话(Conversation) | 标题、类型、消息数、任务数、最后修改时间 | 对话容器 |
| 会话消息(Message) | 角色、文本、素材、参数快照、关联任务Id、配对消息Id、来源任务Id | 对话流的最小单元 |
| 作品(MaterialAsset) | 类型、分组、标签、提示词快照、来源任务、文件信息 | 选秀收录或个人素材 |

### 6.1 任务状态机

```
       提交
        │
        ▼
   pending ──▶ queued ──▶ running ──▶ succeeded
        │         │           │            │
        │         │           │            └──▶ (选秀) 作品库
        │         │           └──▶ failed ◀─┘
        │         └──▶ canceled                ▲
        │                                      │
        └──────────── (取消) ──────────────────┘
```

- `pending`：已落库，待入队
- `queued`：已投递消息，等待 Worker 消费
- `running`：Worker 执行中，伴随进度(0–100)
- `succeeded`：生成完成，产物可读
- `failed`：失败，附错误信息
- `canceled`：用户取消

> 鲁棒性要求：长时间停在 `running` 却无进展的"僵尸任务"须被自动收敛为 `failed`。

## 7. 范围与边界

### 7.1 明确包含
- 图像生成（文生图、图生图）
- 视频生成（全能 / 首尾帧 / 智能多帧）
- 对话式创作、任务管理、作品库、模型配置、会话管理、Agent 建议、实时进度

### 7.2 当前不在范围内（未来规划）
- 多租户 SaaS 化与计费
- 公共分享/外链、团队协作
- 与第三方内容平台（如公众号）的自动发布流水线（见部署方独立规划）
- 模型微调、批量队列调度优先级
- 视频剪辑/合成等后处理

## 8. 验收总则

1. 任意厂商模型，只要填入 endpoint + 密钥 + 匹配预设（或交付模板），即可生成，无需改代码。
2. 三种视频模式互斥且参数合规，违规在提交前被拦截。
3. 进度推送不丢、不卡死；即使实时通道中断，轮询兜底保证最终状态可见。
4. 用户数据严格按 `OwnerId` 隔离。
5. 所有写操作失败有可理解的错误信息，不产生"静默卡住"。
